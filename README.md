# HiPerCalc — 中文超高精度命令行计算器

[English](README.en.md) · **简体中文**

HiPerCalc 是一个使用 Rust 编写的交互式命令行计算器，具备**任意精度小数**、**符号精确运算**、**方程与方程组求解**、**多项式因式分解**等能力。内置 80 位内部计算精度，显示 20 位有效数字，并自带按语法着色的实时高亮 REPL。

---

# 第一部分：功能详解（用户手册）

## 1. 启动与基本使用

```powershell
cargo build
cargo run
```

启动后出现 `> ` 提示符，直接输入表达式回车即可计算，`Ctrl+C` 中断、`/exit` 退出。

```
> 1+2*3
= 7
用时：<1秒
```

第一次使用后，历史输入自动保存到 `~/.hipercalc_history`，下次启动可按 `↑` 回看历史。

### 构建配置说明（debug 速度）

`Cargo.toml` 里对**第三方依赖**开启了优化：

```toml
[profile.dev.package."*"]
opt-level = 3
```

本项目源码保持 `opt-level = 0`（断点与变量查看等调试体验不受影响），但 `num-bigint` /
`num-rational` 等大数库的乘除、取模在未优化时慢一个数量级以上——它们承担了几乎全部重计算的
底层开销。开启后 debug 构建的方程求解等用例普遍提速 **9~13 倍**（如 `e^x=2` 由约 27 秒降到
3 秒、`2^x+3^x=10` 由约 50 秒降到 4 秒），首次构建会多花十几秒重新编译依赖，之后增量不受影响。

### 命令行入口（非交互模式）

默认不带参数即进入交互式 REPL；需要脚本化时显式指定以下参数：

```text
hipercalc -e "1+2*3"           # 只跑一条表达式，打印裸结果行（无耗时行）
hipercalc -f script.hc         # 逐行执行脚本（# 为注释，空行跳过）
hipercalc --stdin < input.txt  # 从标准输入流式执行
hipercalc --lang en -e "1/0"   # 强制界面语言（优先于状态文件，不改配置）
hipercalc -q -e "1+1"          # 不输出耗时行（只作用于本次运行，不改配置）
```

- 退出码：`0` 全部成功、`1` 有求值错误、`2` 参数错误或文件读取失败；
- `-f` / `--stdin` 遇错**继续**执行（错误行照常打印），只要出现过错误，最终退出码为 `1`；
- 非交互模式一律不打印耗时行（`-q` 主要用于交互/管道模式）；
- `-q` / `--no-timing` 与 `--lang` 一样是**本次会话的临时覆盖**，不会写进用户配置——
  想永久关闭请用交互模式下的 `/timing off`；
- **管道/重定向不会自动切换**为无横幅模式：不带参数时仍是"横幅 + `> ` 提示符 + 耗时行"，
  既有验证习惯不受影响。

### 耗时显示

每次运算都会计时：

- **运算进行中**：在算式下一行动态刷新 `用时：N秒`（整秒，只在真实终端里显示，管道/重定向时跳过）；
- **运算完成**：结果打印在该行（**覆盖**刚才的动态耗时），再在结果下一行输出最终耗时
  `用时：N秒`；不足 1 秒显示 `用时：<1秒`。

```
> 2^x=8
用时：0秒            # 动态刷新：1秒 → 2秒 → … → 7秒
x = 3
用时：8秒
```

关闭方式：交互模式下输入 `/timing off`（持久化）；命令行 `-q`/`--no-timing` 只对本次运行生效。
> 升级提示：早期版本存在缺陷——带 `-q` 运行会把 `timing=off` 写进用户配置，导致此后启动都不显示耗时行。
> 若遇到该情况，输入 `/timing on` 即可恢复（该写入路径已修复）。

## 2. 基础运算

| 符号 | 含义 | 示例 |
|---|---|---|
| `+ - * /` | 加、减、乘、除 | `7/2` → `= 3.5` |
| `( )` | 圆括号（改变优先级） | `(1+2)*3` → `= 9` |
| `^` | 幂（右结合，优先级高于乘除） | `2^3^2` = `2^(3^2)` = `512` |
| `ans` | 上一次计算结果（初始为 0） | `ans+1` |

幂运算支持广泛情形：
- 负指数：`2^-2` → `= 0.25`（整数次幂返回精确有理数）
- 分数指数：`8^(1/3)` → `≈ 2`（非整数指数走高精度数值路径，前缀为 ≈）
- 负数底：奇分母有理指数按实数值计算，`(-8)^(1/3)` → `≈ -2`；偶分母或无理指数在实数范围无定义会提示错误

**规模保护**：幂运算会估算结果的十进制位数，超过约 `10^6` 位（或指数大到无法用整数快速幂处理）时
直接报错，而不是给出被截断的错误值：

```
> 2^100000
= 9990020...（约 3 万位整数，整串输出）
> 2^10000000
错误: 幂运算结果约有 3750088 位十进制，超过支持上限（约 10^6 位）
> 2^10000000000
错误: 幂运算结果超出支持范围（指数 × ln(底数) ≈ 10^10，结果约 10^10 位十进制）
```

## 3. 隐式乘法与科学计数法

- **隐式乘法**：数字、变量、括号相邻时自动相乘
  `3x`、`2(3+4)`、`(1+2)(3+4)`、`2|x|` 均合法；常数 `e` 也可作为因子，
  `2ex` → `2*e*x`、`xe` → `x*e`、`ee` → `e^2`。
- **科学计数法（输入）**：数字后跟 `e`/`E` 加整数指数
  `1e3` → `= 1000`、`2.5e-2` → `= 0.025`、`1e0` → `= 1`。

## 4. 常数与精度

| 常量 | 值 |
|---|---|
| `pi` / `π` | 圆周率 ≈ 3.14159… |
| `e` | 自然常数 ≈ 2.71828… |

- 常数：`pi`/`π`、`e`、`i`（虚数单位）、`tau`（= 2π，精确，MathIO 显示为 `2*pi`）、`phi`/`φ`（黄金比 `(1+√5)/2`，精确）；
- 内部统一使用 **工作精度（默认 80 位小数）** 参与计算，可用 `/mode prec N` 调整（20 ~ 2000）；
- 显示时四舍五入到 **20 位有效数字**（可除尽的小数则输出全部数字）；
- **大数显示**：整数部分超过 20 位时改用科学计数法，保留量级（不丢高位）：

```
> 10^25/3
≈ 3.3333333333333333333×10^24
> exp(60)
≈ 1.1420073898156842837×10^26
> 123456789012345678901234567890/7
= 17636684144620811271604938270      （整数原样整串输出）
```

- **参数上限**：`exp`/`sinh`/`cosh` 的参数 |x| > 10^6 时报错（结果位数会失控）；
  `tanh` 例外（|x| > 100 时结果在 80 位精度下已饱和，直接返回 ±1，不报错）；
  三角函数的弧度参数 |x| ≥ 10^78 时报错（80 位精度的 π 参数归约会失效，结果不可靠）。

### 计算模式 `/mode fast` / `/mode deep`

| 模式 | 行为 |
|---|---|
| **Fast**（默认） | 保留规模保护：`exp`/幂/三角/阶乘/科学计数法指数超出上限时**直接返回提示**；因式分解候选枚举有预算，超预算提示"结果可能不完整"；显示 20 位有效数字（整数部分 > 20 位时用科学计数法） |
| **Deep** | **死算**：取消上述全部规模上限，**完整精度输出**（不截断、不用科学计数法）。极端输入可能长时间无响应、产生超长输出甚至耗尽内存，请自行判断 |

```
> 10^25/3
≈ 3.3333333333333333333×10^24        # Fast
> /mode deep
已切换到死算模式 (Deep)：不设规模上限、完整精度输出（不走科学计数法）；极端输入可能长时间无响应或产生超长输出
> 10^25/3
≈ 3333333333333333333333333.33333333333333333333333333333333333333333333333333333333333333333333333333333333
> 1/2^70
= 0.0000000000000000000008470329472543003390683225006796419620513916015625
> 2^10000000                             # Fast 会提示超限，Deep 真的去算（约 300 万位）
```

说明：

- Deep 只放开**规模**上限，**不放开牛顿迭代的发散保护**——否则 `2^x=8` 这类方程会回到卡死状态；
- Deep 下 `2^10000000000`、`1e10000000000` 之类的输入会真的尝试构造天文位数的整数，几乎必然耗尽内存，请避免；
- `sqrt` 化简、因式分解的候选枚举在 Deep 下可能长期运行（例如大 Δ 的平方因子试除）；
- 三个模式（显示 / 角度 / 计算）都会随 `~/.hipercalc_state` **持久化**，重启后自动恢复（详见第 10 节）。

## 5. 函数一览

### 函数形式（白名单）

| 类别 | 函数 | 说明 |
|---|---|---|
| 开方 | `sqr(x)`、`sqrt(x)` | 平方根（负数给纯虚根，见"复数支持"） |
| 复数 | `re(z)` `im(z)` `conj(z)` `arg(z)` | 实部 / 虚部 / 共轭 / 辐角（弧度）；**实数入参同样可用**（`re(2) = 2`、`im(2) = 0`、`arg(-1) = π`） |
| | `cbrt(x)` | 立方根；允许负数（奇次），完全立方给精确值（`cbrt(-27)` → `= -3`、`cbrt(1/8)` → `= 0.5`） |
| 绝对值 | `abs(x)`、`|x|` | 两形式等价 |
| 三角 | `sin cos tan cot sec csc` | 受角度模式（弧度/度）影响 |
| 反三角 | `arcsin arccos arctan arccot arcsec arccsc` | 特殊值返回精确角 |
| 对数 | `ln(x)` | 自然对数，`x>0` |
| | `log(b, x)` | 任意底对数：`log(2, 8)` → `= 3` |
| | `log10(x)`、`log2(x)` | 常用/以 2 为底对数 |
| 指数 | `exp(x)` | `e^x` |
| 取整 | `floor(x) ceil(x) round(x)` | 下取整/上取整/四舍五入 |
| 小数 | `frac(x)` | `x - floor(x)`，取值 `[0,1)` |
| 符号 | `sign(x)` | `-1 / 0 / 1` |
| 双曲 | `sinh cosh tanh` | 双曲正弦/余弦/正切 |
| | `coth sech csch` | 双曲余切/正割/余割（`coth(0)`、`csch(0)` 未定义会报错） |
| 反双曲 | `arcsinh(x)` | 反双曲正弦（全体实数有定义） |
| | `arccosh(x)` | 反双曲余弦，定义域 `x >= 1` |
| | `arctanh(x)` | 反双曲正切，定义域 `|x| < 1` |
| 数论 | `gcd(a,b)` `lcm(a,b)` | 最大公因数 / 最小公倍数（非零整数，结果恒非负） |
| | `primefac(n)` | 素因数分解（须为最外层）：`primefac(12)` → `12 = 2^2 * 3` |
| | `isprime(n)` `nextprime(n)` | 素性判定 / 下一个素数（见"二元函数"） |

新增函数只需改 **两处**：`parser.rs` 的 `FUNCTIONS` 常量（解析校验、多字母拆分、REPL 高亮共用同一份）、
`Evaluator::eval_function`。`fact`/`abs` 作为内部名不要加进白名单。

### 后缀阶乘 `!`

紧贴操作数，**优先级高于幂**：

```
> 5!
= 120
> (2+3)!
= 120
> 2^3!        # = 2^(3!) = 2^6
= 64
```

参数须为非负整数，上限 10000。

### 绝对值 `| |`

优先级与括号相同，支持嵌套与任意组合：`|-5|`、`|x-3|`、`2|x|`、`|2*3-1|`、`||-3||` 均可用。

### 对数的精确识别

- 真数为 2/10 的整数次幂时 `log2`/`log10` 直接返回精确整数：`log2(8)` → `= 3`；
- `log(b, x)` 在底数与真数**同为某数的整数次幂**时给出精确有理数：

```
> log(3, 27)
= 3
> log(8, 1/2)
≈ -0.33333333333333333333   （LineIO 下 -1/3 为循环小数，MathIO 显示 = -1 / 3）
> log(12, 144)
= 2
> log(2, 2^100)
= 100
> log(e, e)
= 1
```

其余情形走 `ln(x)/ln(b)` 高精度近似，如 `log(2, 3)` → `≈ 1.5849625007211561815`。

## 6. 显示模式与 `=` / `≈` 语义

| 模式 | 行为 |
|---|---|
| **MathIO**（数学显示） | 优先输出**精确符号**形式：整数、最简分数、根号、`pi`、`e`；无法精确表示时退化为小数 |
| **LineIO**（线性显示，默认） | 一律输出小数（可除尽则全部数字，否则 20 位有效数字；整数部分超过 20 位时用科学计数法） |

结果前的符号表示**精确程度**：

- `= ` 表示该输出是精确值（MathIO 下的整数/分数/根式；LineIO 下能完整写出的整数与有限小数）；
- `≈ ` 表示近似值（无限小数、无理数，以及 LineIO 下**有效数字超过 20 位**的有限小数，
  例如 `1/2^70` 会被四舍五入到 20 位有效数字，因此标 `≈`）。

> `/mode deep` 下不截断、完整输出，因此有限小数（如 `1/2^70`）一定标 `=`。

`sd(x)` 是强制显示转换：MathIO 下转为小数、LineIO 下尝试转为符号形式。它必须是整个表达式的最外层函数。
转换结果的前缀按**转换后**的形式判定精确性：LineIO 下 `sd(1/3)` → `= 1 / 3`（精确符号）、
`sd(sin(1))` → `≈ 0.84147…`（近似值仍只能给小数）；MathIO 下 `sd(1/2)` → `= 0.5`（能完整写出的小数）、
`sd(1/3)` → `≈ 0.33333…`（循环小数）。

## 7. 方程求解

输入含单个 `=` 的表达式会被识别为方程并求解：

| 输入 | 输出 |
|---|---|
| `x^2-4=0` | `x = 2, x = -2` |
| `x^2+1=0` | `x = 0 + 1i, x = 0 - 1i`（复数根） |
| `x^3-6x^2+11x-6=0` | `x = 1, x = 2, x = 3`（全部根） |
| `1/x=2` | `x = 0.5` |
| `2^x=8` | `x = 3` |
| `e^x=2` | `x ≈ 0.69314718055994530942` |

> 根与普通结果一样**按显示模式输出**并带 `=`/`≈`：LineIO 下一律小数
> （`1/x=2` → `x = 0.5`、`x^2=2` → `x ≈ 1.4142135623730950488`），
> MathIO 下精确根用符号形式（`x = 1 / 2`、`x = sqrt(2)`）。
>
> 指数/对数型方程走数值牛顿迭代，debug 构建下可能需要几秒（每步都要高精度 `ln`/`exp`）；
> 若牛顿迭代发散（修正量或 |x| 超过 10^6）会立即放弃该初值，不会出现卡死。
> 高次方程（次数 > 200）在 Fast 模式下直接报 `数值求根次数过高…请先执行 /mode deep`，
> **不会**退化成单根牛顿（那会让界面长时间无响应，且只给一个根）。

### 无穷解的通式表示

三角函数方程有无限多解，程序以周期通式给出**所有解**；通式的单位跟随当前角度模式
（弧度模式给 `k·π`，角度模式给度数）：

```
> /mode rad
> cos(x)=0
x = π/2 + k·π，k 为整数
> sin(x)=0.5
x = π/6 + k·2π  或  5π/6 + k·2π，k 为整数
> sin(x)=0
x = k·π，k 为整数

> /mode deg
> cos(x)=0
x = 90 + k·180，k 为整数
> sin(x)=0.5
x = 30 + k·360  或  150 + k·360，k 为整数
> sin(x)+cos(x)=1
x = k·360  或  90 + k·360，k 为整数
```

**识别原理**（`solve_aux::format_periodic_roots`）：把收集到的实根先**折算成弧度**，
再检查相邻差是否"全部相等"（单族）或"两类严格交替"（两族）⇒ 定出公共周期 `d`，
再把 `d` 与各残基用**分母不超过 12 的有理逼近**表示成 `(p/q)·π`，最后按当前单位渲染
（弧度 `π/6` / 角度 `30`）。三点约定：

- 判定前只保留 `±3π` 窗口内的根——牛顿从远处的初值可能落到很远的根（如 `sin(x)+cos(x)=1`
  会混进 ≈29.8 这类根），它们会让相邻差不再规整、把整条通式判否；窗口**只影响判定**，
  不影响回退分支里列出的全部根；
- 方程含**以未知量为角度的三角函数**（`sin(x)` 这类）时，角度模式下的初值按 `×180/π` 换算，
  使牛顿轨迹与弧度模式在物理上完全一致；不含三角的方程（`1/x=2`）初值不变；
- 判不出周期结构的方程（如 `sin(x)=x/10`）**不会**硬套通式，仍逐根列出。

### 求解策略

- 多项式方程：线性/二次**精确求解**；高次多项式用 **Durand-Kerner 迭代求全部复数根**；
- 含超越函数（cos、ln、log 等）的方程：**牛顿迭代**，多组由近及远的初始猜测（含 π/2 整数倍以覆盖三角零点），并对最终残差校验以剔除假根；
  角度模式下若方程含**以未知量为角度的三角函数**（`sin(x)` 这类），初值整体 `×180/π` 换算，
  使牛顿轨迹与弧度模式一致（否则 `±k·π ≈ ±3.14°` 太小、`±1..±6` 又会过冲）；
  只落在复数域的初值（如 `ln(-1)`）直接放弃，不参与求根；
  单步修正量或 |x| 超过 10^6 视为发散，直接放弃该初值（指数/对数型方程的常见发散形态）；
- 结果若可识别为简单分数/根式则回填精确值（如 `abs(x)=1` 输出 `x = 1, x = -1` 而非约等）；
  回填值同样按显示模式输出（LineIO `1/x=2` → `x = 0.5`，MathIO → `x = 1 / 2`）；
  容差按量级缩放，极小根不会被回填成 `0`（如 `arctan(x)=1e-30` → `x ≈ 0.000000000000000000000000000001`）。

## 8. 方程组

用**逗号分隔**多个等式构成方程组：

```
> x+y=5, 2x-y=1
x = 2, y = 3
```

- **线性方程组**：高斯消元，无解/无穷多解会给出提示；解按当前显示模式输出并带 `=`/`≈` 精确度前缀
  （LineIO 下 `3x=1, y=1` → `x ≈ 0.33333333333333333333, y = 1`；MathIO 下 → `x = 1 / 3, y = 1`）；
- **非线性方程组**：多维牛顿法，先在网格初值上**粗略扫描**（前向差分、松容差）收集候选，再对候选**精细收敛**（中心差分、高容差），多解自动去重；
  收敛后必须再校验残差（避免返回平坦区假根），任一分量超过 10^6 视为发散并放弃该初值。

## 9. 因式分解 fac / factor 与素因数分解 primefac

- `fac` 与 `factor` 等价，必须是整个表达式的最外层函数；
- **参数恰好是非零整数时**（`fac(12)`）自动做**素因数分解**，与 `primefac(12)` 等价（见下）；
  其余情况仍做多项式分解；
- 分解域由当前显示模式决定：
  - **MathIO → 实数域**：二次因式可拆出 `sqrt` 根式；
  - **LineIO → 有理数域**：仅整数/分数系数，不可再分时提示；
- 支持 **1~3 个变量**，支持大系数与齐次提升；
- `ans` 与 `/let` 存储的全大写变量按**当前数值**代入（与方程求解一致）：
  `/let A=4` 后 `fac(x^2-A)` → `= (x - 2) * (x + 2)`；
- **规模上限**：有理根候选（系数 > 10^13 时放弃枚举）与二次因子枚举都有预算，
  且预算按**工作量**折算（试算次数 × 多项式次数 ≤ 4×10^4），高次多项式会自动少试算；
  超出预算时结果会附加 `（候选枚举超出规模上限，结果可能不完整）`，不会长时间卡住。

```
> fac(x^2-4)
= (x - 2) * (x + 2)
> fac(12)
12 = 2^2 * 3
> fac(360)
360 = 2^3 * 3^2 * 5
> fac(x^2-y^2)
= (x - y) * (x + y)
> fac(x^3-8)
= (x - 2) * (x^2 + 2x + 4) （有理数域内不可再分解）
> fac(x^2-2)
= (x^2 - 2) （有理数域内不可再分解）      # LineIO：有理数域内不可再分
> /mode mathio
> fac(x^2-2)
= (x - sqrt(2)) * (x + sqrt(2))          # MathIO：实数域内可拆根式
> fac(100000000000000*x^2 + 100000000000001*x + 1)
= (100000000000000*x^2 + 100000000000001*x + 1) （候选枚举超出规模上限，结果可能不完整）
```

> LineIO 下保留的二次因式（如 `x^2-2`）在有理数域内确定不可再分解（有理根枚举已全部失败），
> 故一定附加 `（有理数域内不可再分解）`；MathIO 下同样的二次因式若能拆成 `sqrt` 根式则不加提示。

### 素因数分解 `primefac(x)`

把整数分解成素因数的乘积，输出 `x = …` 的等式形式：

- **只能是整个表达式的最外层函数**（与 `sd`/`fac`/`triangle` 同一约定）；
- 参数**必须是非零整数**：小数、`0` 一律报错（`2+3` 这类可求值的表达式没问题）；
- 结果按素因数**升序**排列，重复的因数用**指数**表示，指数为 1 时省略 `^1`；
- **负数把负号顶在最前面**：`-12 = -2^2 * 3`；`1`/`-1` 没有素因数，直接输出 `1 = 1` / `-1 = -1`；
- **规模护栏**：Fast 模式下试除数不超过 `10^6`；若分解完小因子后剩下的部分还是合数
  （即含 > 10^6 的素因子），直接提示 `素因数分解超出试除预算…请先执行 /mode deep`，
  而不是给出残缺结果；`/mode deep` 取消预算（可能极慢）。

```
> primefac(12)
12 = 2^2 * 3
> primefac(-12)
-12 = -2^2 * 3
> primefac(360)
360 = 2^3 * 3^2 * 5
> primefac(7)
7 = 7
> primefac(2+3)          ← 括号内是可求值的表达式
5 = 5
> primefac(-2^2)         ← -2^2 = -(2^2) = -4
-4 = -2^2
> primefac(0)
错误: primefac 的参数必须是非零整数
> primefac(2.5)
错误: primefac 的参数必须是非零整数
> 2*primefac(12)
错误: primefac() 必须是整个表达式的最外层函数，不能参与其它运算
```

### 多项式函数拟合（输入坐标即可求函数）

直接输入坐标就能求出过这些点的多项式函数：**2 个坐标求一次、3 个求二次、依次类推**。
坐标后可以跟"带参数的解析式"，则解出未知参数并给出完整解析式；参数不足以确定时输出参数关系。

```
> (1,2) (3,4)
y = x + 1

> (0,1) (1,3) (2,7)
y = x^2 + x + 1
y = (x + 1 / 2)^2 + 3 / 4          ← 二次函数自动追加顶点式

> P(1,3) (0,0)                     ← P 表示顶点（提供 f(1)=3 与 f'(1)=0 两个约束）
y = -3*x^2 + 6*x
y = -3*(x - 1)^2 + 3

> (0,1) (1,3) (2,7) y = a*x^2+b*x+c
a = 1, b = 1, c = 1
y = x^2 + x + 1
y = (x + 1 / 2)^2 + 3 / 4

> (0,1) (1,3) y = a*x^2+b*x+c      ← 参数欠定：给关系式，解析式也用关系表达
a = 2 - b
c = 1
自由参数: b
y = (2 - b)*x^2 + b*x + 1
```

| 规则 | 说明 |
|---|---|
| 坐标 | `(x, y)`；分量可写负数、小数、分数、`pi`、`sqrt(2)` 等任意表达式 |
| 顶点 | **只有大写 `P`**：`P(x, y)` 表示函数顶点（相当于两个约束）。小写 `p` 仍是普通变量；写成 `p(x,y)` 会提示改用大写 |
| 约束计数 | 普通坐标 1 个约束，顶点 2 个；约束数 − 1 = 次数 |
| 解析式模板 | 跟在坐标后，可写 `y = …` / `f(x) = …` / 不写左值（**输出恒为 `y = …`**，左值只是装饰） |
| 未知参数 | 模板里出现、但无法确定值的字母（自变量固定为 `x`）；`pi`/`e`/`i` 等常数与 `/let` 存过的变量算**已知** |
| 模板化简 | 任意书写形式都会自动展开合并同类项，例如 `a*x^2+a*x+b*x+c` ⇒ `(a + b)*x^2 + …` |
| 欠定 | 坐标不足时输出"主元参数 = 自由参数的表达式"与 `自由参数: …` 一行，解析式同样用关系表达 |
| 顶点式 | 仅"实际二次（首项非 0）且系数全为常数"时追加，形如 `y = a*(x - m)^2 + k` |
| 规模上限 | Fast 模式下"约束/参数"不超过 16 个（次数 ≤ 15），超出提示 `/mode deep`；Deep 放开 |
| 不支持 | 模板必须化简为**关于 x 的多项式**（`sin/log` 之类会明确报错）；超定且矛盾时直接报矛盾（不做最小二乘） |

示例：`/let A=2` 后输入 `(0,1) (1,3) y = A*x + b` ⇒ `b = 1` 且 `y = 2*x + 1`（`A` 已知，只解 `b`）。

### 三角形求解（`triangle(...)` 一键求出其余全部量）

把已知的边、角、高填进 `triangle(...)`，即可求出三角形的全部量：

```
> triangle(a=3 b=4 c=5)
a = 3, b = 4, c = 5
A ≈ 36.869897645844021297, B ≈ 53.130102354155978703, C = 90
hA = 4, hB = 3, hC = 12 / 5
面积 = 6, 周长 = 12
外接圆半径 = 5 / 2, 内切圆半径 = 1

> triangle(A=30, b=5, C=60)        ← 逗号分隔亦可
a = 5 / 2, b = 5, c = 5*sqrt(3) / 2
A = 30, B = 90, C = 60
hA = 5*sqrt(3) / 2, …

> triangle(hA=4 a=3 b=4)           ← 高 + 底边 → 面积，再归约成 SAS
a = 3, b = 4, c = 5
A ≈ 36.869897645844021297, B ≈ 53.130102354155978703, C = 90
…

> triangle(a=4 b=5 A=30)           ← SSA 两解：逐组列出
解 1:
a = 4, b = 5, c ≈ 7.4526260181213923367
…
解 2:
a = 4, b = 5, c ≈ 1.2076280197229941309
…

> triangle(hA=2 hB=3 hC=4)
错误: 已知信息不足，无法确定三角形（形状已确定 a : b : c = 6 : 4 : 3，仅缺一个长度）
```

| 规则 | 说明 |
|---|---|
| 输入 | `triangle(a=3 b=4 c=5)`，括号内是 `<记号>=<值>`；**空白或逗号分隔**均可（括号内的逗号若是函数参数，如 `log(2,8)`，不会被当分隔符） |
| **只能最外层** | 与 `sd(...)`/`fac(...)` 同一约定：`triangle(...)` 必须是整个表达式的最外层函数。写成 `2*triangle(...)`、`triangle(...)+1` 都会明确报"必须是整个表达式的最外层函数" |
| 记号 | 边 `a,b,c`；角 `A,B,C`（`A` 对边 `a`）；高 `hA,hB,hC`（`hA` 为 BC 边即 `a` 边上的高） |
| 角度单位 | 跟随当前 `/mode deg\|rad`：`deg` 下 `A=30` 即 30°；`rad` 下要写 `A=pi/6`（写 `A=30` 会因 30 弧度 > 180° 报错） |
| 值的写法 | 任意表达式：`a=1/2`、`b=sqrt(2)`、`hA=3*sin(30)` 都可以 |
| 求解策略 | SSS/SAS/ASA/AAS/SSA 与"高可归约"的情形走**公式解析解**；其余组合走**数值兜底** |
| 高的归约 | `hA·a = 2S`（高×底边→面积）、`hA = b·sinC = c·sinB`（高×邻角→邻边）、`a·hA = b·hB`（两条高→边长比） |
| 多解 | `SSA`（`b·sinA < a < b`）与"两边+面积"等情形会有两组解，逐组以 `解 1:` / `解 2:` 列出 |
| 精确性 | `triangle(a=3 b=4 c=5)` 给出 `C = 90`（精确）、`面积 = 6`、`R = 5 / 2`、`r = 1`；非特殊角标 `≈` |
| 已知量优先 | 回代校验通过后，已知量原样写回（`A=30` 就显示 `30`，不会是 `29.9999…`） |
| 校验 | 三角不等式、内角和、超定一致性都校验；矛盾时明确报"已知量之间存在矛盾" |
| 不冲突 | `a=3`（解方程）、`a=3, b=4, c=5`（解方程组）、`x=1 y=2` 等既有写法**行为完全不变**；旧的裸写 `a=3 b=4 c=5` 已取消（现在会报"多余的字符"），避免与方程组/隐式乘法混淆 |


### 复数支持

`i` 是**虚数单位常数**（与 `pi`/`e` 同级），可以直接参与运算：

```
> (2+3i)*(1-i)
= 5 + i
> i^2
= -1
> 1/(1+i)
= 0.5 - 0.5i
> sqrt(-4)
= 2i
> ln(-1)
≈ 3.1415926535897932385i
> abs(3+4i)
= 5
> exp(i*pi/2)
≈ 1i
```

| 能力 | 说明 |
|---|---|
| 四则运算 | 加、减、乘、除（除法走共轭），`Gaussian` 有理数结果**精确** |
| 整数幂 | 快速幂（`i^100 = 1`、`(2i)^3 = -8i`），负整数幂给倒数 |
| 开方 | `sqrt`/`sqr`：负实数给纯虚根（`sqrt(-4) = 2i` 精确，`sqrt(-2) = √2·i`）；复数的平方根走极坐标 |
| 超越函数 | `exp`、`ln`、`sin`/`cos`/`tan`（数值，`BigFloat` 内部按**弧度**计算） |
| 分量操作 | `abs(z)` 取模、`re(z)` 实部、`im(z)` 虚部、`conj(z)` 共轭、`arg(z)` 辐角（弧度）；这四个**对实数同样有定义**（实数 = 虚部为 0 的复数）：`im(2) = 0`、`arg(-1) = π`、`arg(0)` 报"0 没有辐角" |
| 不支持 | 非整数次幂（`i^(1/2)` 报错）、`floor`/`ceil`/`round`/`frac`/`sign`/`mod`/`idiv`/`gcd`/`nCr`/反三角等实函数（报 `复数不支持该函数: xxx`）、以复数为未知数的方程 |

**显示格式**：`a + bi` / `a - bi`；实部为 0 时省略（`2i`、`-i`）；虚部为 ±1 时省略系数（`i`、`-i`）；
虚部是分数/根式时加括号（`(1 / 2)i`）。前缀 `=` 要求实部与虚部都能精确呈现，否则 `≈`。

**相对旧版本的行为变更**（升级须知）：

- `i` 不再是小写单字母未知数 ⇒ `i^2-4=0` 这类"以 i 为未知数"的方程不再有效（现在会提示"方程中没有变量"）；
  需要变量时改用其它字母（`x`、`y`…）；
- `sqrt(-4)`、`sqr(-2)`、`ln(-1)` 由"报错"改为给出复数结果（实数域无定义，复数域有定义）；
- 奇次根不受影响：`cbrt(-8) = -2` 仍在实数域。

### 工作精度与显示格式（`/mode prec|digits|sci|group`）

| 指令 | 作用 | 取值范围 |
|---|---|---|
| `/mode prec N` | 工作精度（内部小数位数），默认 80 | 20 ~ 2000 |
| `/mode digits N` | 显示有效位数，默认 20 | 1 ~ 当前工作精度 |
| `/mode sci on\|off` | 是否在大数显示时使用科学计数法（默认 `on`） | —— |
| `/mode group on\|off` | 整数部分是否加千分位分隔（默认 `off`） | —— |

```
> /mode prec 40
已设置工作精度为 40 位小数（显示 20 位有效数字）
提示: 显示位数（20）少于工作精度，可用 /mode digits 提高
> /mode digits 30
已设置显示 30 位有效数字
> pi
≈ 3.14159265358979323846264338328
> /mode group on
已开启千分位分隔
> 1234567*1000
= 1,234,567,000
> /mode sci off
已关闭科学计数法显示（大数完整写出）
> 10^25/3
≈ 3,333,333,333,333,333,333,333,333.33333
```

- 四项设置都**立即落盘**（状态文件里的 `prec=`/`digits=`/`sci=`/`group=`），重启后保持；
- 切换工作精度**不会**重算已有变量与 `ans`（`Exact` 与精度无关，`Approx` 保留自身精度）；
  常数缓存（π/e/ln2/小整数 ln）按目标精度分桶，切换后自动按新精度重算并各自缓存；
- 精度越高越慢（`/mode prec 2000` 配合大数运算可能明显变慢）；`/mode prec` 只校验范围，不提示耗时；
- 非默认的精度/显示设置会追加到启动横幅的模式串后（如 `LineIO/Degree/Fast/简体中文/40/30/sci-off/group`），
  默认设置下横幅保持 `LineIO/Radian/Fast/简体中文` 四段式；
- 千分位只作用于**纯十进制**结果（分数 `1 / 2`、根式 `sqrt(2)`、科学计数法、含 π 的符号串不会被加逗号）。

### 二元函数（取模 / 整除 / 开方 / 组合 / 数论）

| 函数 | 说明 |
|---|---|
| `nroot(x, n)` | `x` 的 `n` 次根（`n` 为 2 ~ 1000000 的整数）；完全 `n` 次幂给**精确值**（`nroot(16,4)` → `= 2`），否则数值；负数只在 `n` 为奇数时有定义 |
| `mod(a, b)` | **Euclidean 取模**：结果恒满足 `0 ≤ r < |b|`（`mod(-7,3)` → `= 2`、`mod(7,-3)` → `= 1`） |
| `idiv(a, b)` | **Euclidean 整除**（对应 Rust 的 `div_euclid`）：`a = b·idiv + mod`（`idiv(-7,3)` → `= -3`、`idiv(7,-3)` → `= -2`） |
| `nCr(n, r)` / `nPr(n, r)` | 组合数 / 排列数，参数须为非负整数；`r > n` 得 `0`；Fast 模式 `n ≤ 10000`（Deep 放开） |
| `gcd(a, b)` / `lcm(a, b)` | 最大公约数 / 最小公倍数，参数须为**非零整数**（小数与 `0` 报错）；**结果恒为非负**，可参与其它运算（`2*gcd(12,18)` → `= 12`） |
| `primefac(n)` | **素因数分解**，须为整个表达式的最外层函数（详见第 9 节）：`primefac(12)` → `12 = 2^2 * 3` |
| `isprime(n)` | 素性判定，返回 `1`/`0`（小素数试除 + 12 底 Miller-Rabin，`n < 3.3×10^24` 内是确定性判定） |
| `nextprime(n)` | 大于 `n` 的最小素数（`nextprime(0)` → `2`） |

- `mod`/`idiv` 要求**精确数值**（`mod(pi,2)` 会报错），除数为 0 也会报错；
- **三套除法的语义别混**：`mod`/`idiv` 是 Euclidean（余数非负）、`bigint_ext::div` 是截断除法（余数符号随被除数）、
  普通 `/` 走有理数精确除法；
- 素性判定的 Fast 上限为 `10^24`（12 个底的 Miller-Rabin 在 `3.3×10^24` 内确定性），Deep 模式不设上限。

### 反双曲函数说明

三者都用 `ln`/`sqrt` 组合实现（复用既有高精度数值层），因此**只看数值、不产生精确形式**
（`arcsinh(0)`、`arccosh(1)`、`arctanh(0)` 这类零点仍给精确的 `0`）：

- `arcsinh(x) = sign(x)·ln(|x| + √(x²+1))` —— 用 `|x|` 入对数，负数取反，避免 `ln(负数)`；
- `arccosh(x) = ln(x + √(x²-1))`，`x < 1` 报"定义域"错误；
- `arctanh(x) = ½·ln((1+x)/(1-x))`，`|x| ≥ 1` 报"定义域"错误；`|x|` 极接近 1 时结果非常大，
  80 位精度下有效数字会明显减少（输入本身的精度被放大）。

## 14. 核心数据结构

### BigFloat（bigfloat.rs）

任意精度浮点，本质是 **BigInt 尾数与 10 的负精度**：

```rust
pub struct BigFloat {
    pub value: BigInt,      // 尾数（缩放至 10^precision）
    pub precision: usize,   // 小数位数
}
```

即 `值 = value / 10^precision`。关键常量：

- `PRECISION = 80`：内部计算精度（小数位数）
- `MARGIN = 20`：运算保留的额外余量，避免中间结果截断
- `DISPLAY_DIGITS = 20`：LineIO 输出有效数字位数
- `EXP_ARG_LIMIT_LOG10 = 6.0`：`exp` 参数量级上限（|x| ≤ 10^6）
- `MAX_RESULT_DIGITS = 1e6`：幂等结果十进制位数上限

所有运算返回 `BigFloat` 后在目标精度 `round_to` 收尾。**四则运算直接操作 BigInt**；`sqrt` 用整数平方根做初值再牛顿迭代；`ln` 先将参数缩放为 `x = s·2^m`（`s∈[1,2)`）后用 `atanh` 级数收敛，`ln(2)` 由 `2·atanh(1/3)` 显式算出——这是大参数下仍保持 20 位正确数字的关键。

**常数缓存**（`pi` / `e` / `ln2` / 小整数 `ln`）：

- 三者的计算都是迭代/级数（π 为 Gauss-Legendre、e 与 ln2 为无穷级数），单次开销远高于一次四则运算；
- 而它们会被高频重复调用：`pow` 走 `exp(b·ln a)` 每次都要 ln2，三角归约每次都要 π，`ExactExpr::to_bigfloat` 每遇到 `Pi`/`E` 项都要重算——**牛顿迭代求解方程时每轮求值都会碰到**；
- 因此三者都按**目标精度**（`HashMap<usize, BigFloat>` + `OnceLock`/`Mutex`）缓存，`ln2` 抽为 `ln2_cached`；
- **小整数 `ln` 缓存**（`HashMap<(BigInt, usize), BigFloat>`，容量 64 满则清空）：`pow(a, b)` 每轮都要算 `ln(a)`，
  而指数方程（`3^x=27`）迭代中底数固定、`ln(3)` 却被反复重算（atanh 级数约百项）；
  只缓存 2..=10^6 的整数底数（任意参数不入表，避免污染），实测 `3^x=27` 由 5 秒降到 3 秒、`5^x=125` 由 2 秒降到 1 秒；
- 缓存只影响速度：命中即返回同精度的相同值，未命中照常现算，锁中毒时静默跳过缓存。
  实测缓存后方程组类求解约提速 4 倍，是 `2^x=8` 这类方程从数十秒降到数秒的关键之一。

**数值稳定性与规模保护**（防止"静默错误/卡死"）：

- `exp(x)`：先把参数缩半到 `|x| ≤ 1`（`exp(x) = exp(x/2^k)^(2^k)`）再展级数，
  收敛判据是**相对**判据 `|term| ≤ |result|·10^-work_prec`；参数超过 `EXP_ARG_LIMIT_LOG10` 直接报错。
  （旧实现用绝对判据且无参数上限，|x| 很大时级数永不收敛、中间量整数位数爆炸 ⇒ 卡死 + 结果错误）
- `pow(a, b)`：整数指数走快速幂并做结果位数保护；一般情形先检查 `|b·ln a|` 是否超限，超出即报错，
  不再静默返回被截断的级数和。
- `sqrt`/`ln`/`atan`：参数先缩到收敛域内再展级数，收敛域不可随意改动。

### 大数显示规则

`to_significant_string(max_digits)`：小数位数不超上限时整串输出；**整数部分超过 `max_digits` 时改用
科学计数法**（`d.ddd×10^n`，保留量级）。旧实现直接按字符串截断，会把整数部分的低位连同数量级一起丢掉
（`10^25/3` 曾显示成 `3.3e19`）。

### 大整数除法与开方（bigint_ext.rs）

大整数运算按规模分派：小规模走 num-bigint 原生实现（快），大规模改走自带的 Knuth D 教材式长除法与
牛顿整数平方根。原因是 num-bigint 0.4.7 的 Burnikel-Ziegler 除法在"被除数 ≈ 除数²"的形状下会
触发 `debug_assert!(ah < b)`，直接 panic 退出进程——实测 `sqr(10^100000)`、
`(10^200000+pi)/(10^100000+pi)` 都属于这一类。`bigint_ext.rs` 另带 `#[cfg(test)]` 单元测试
（除法恒等式 `a = q·b + r`、平方根 `s² ≤ n < (s+1)²`），`cargo test` 可跑。

### calc_mode（calc_mode.rs）

进程级计算模式开关（`AtomicBool`）：`Fast`（默认）/ `Deep`。

- 为什么是全局变量：规模护栏分散在 `bigfloat.rs` / `number.rs` / `parser.rs` / `solver_factor.rs` 的
  低层数值函数里，它们拿不到 `Evaluator` 上下文；REPL 是单线程执行运算，用原子布尔量同步即可。
- 各护栏统一用 `crate::calc_mode::is_deep()` 判断是否放行：

| 位置 | Fast 行为 | Deep 行为 |
|---|---|---|
| `bigfloat::exp` / `pow` | 超 `EXP_ARG_LIMIT_LOG10` / `MAX_RESULT_DIGITS` 报错 | 不拦截 |
| `number::check_pow_scale` | 结果位数超 10^6 报错 | 不拦截 |
| `parser::check_exp_range` / `check_trig_range` | 参数超限报错 | 不拦截 |
| `parser` 阶乘上限 10000、科学计数法指数上限 10^5 | 报错 | 不拦截 |
| `solver_factor` 的因子枚举 / 开方化简 / 二次因子预算 | 到上限即停止并提示"可能不完整" | 不设上限（可能极慢） |
| `solver_poly::durand_kerner` 次数上限 200 | 高次因子（> 200 次）提示"请用 /mode deep" | 不设上限（可能极慢） |
| `bigfloat::to_significant_string` | 20 位有效数字 / 大数用科学计数法 | 完整精度，不用科学计数法 |
| `newton_solve` / `solver_nonlinear` 发散保护 | **保留** | **保留**（否则 `2^x=8` 会卡死） |

### Number（number.rs）

双重表示：能算就精确，算不了才近似：

```rust
pub enum Number {
    Exact(ExactExpr),   // 符号精确：有理数 + sqrt/pi/e 项
    Approx(BigFloat),   // 高精度近似
}

pub struct ExactExpr {
    pub terms: Vec<ExactTerm>,   // Rational(|p/q) | Sqrt(coeff, radicand) | Pi(coeff) | E(coeff)
    pub denominator: BigInt,     // 分母（正整数）
}
```

运算管线（顺序不可调换）：**清零项 → `normalize_terms`（把 `Sqrt(x,1)` 归一为有理数）→ `simplify_expr`（合并约分、分母有理化）**。`Exact + Exact` 合并失败才回退 `Approx`。除法中 `div_exact` 先处理"除数分母 ≠ 1"（如 `sqr(2)/2`），再走单个 sqrt / 共轭有理化分支，是分母有理化正确性的关键。

**易错点（已修正，勿回退）**：

- `div_exact` 的"除数为单个 sqrt 项"分支：`self/(c·√r) = self·√r·(1/(c·r))`，
  `1/(c·r)` 必须作为**有理因子**乘进各项系数（`scale_term_rational`），
  不能只取 `c.numer()*r`（会丢掉系数分母，`1/(sqr(2)/2)` 少除 2 倍）。
- `Number::int_pow` 展开 `(a√b)^n` 时必须用 `a` 的**有理数**幂：
  `n=2m` 偶 → `a^(2m)·b^m`；`n=2m+1` 奇 → `a^(2m+1)·b^m·√b`。
  （旧实现用 `numer/denom` 整数截断，`1/2` 变 0；偶数次幂还少乘一次 `a`：`(2√3)^2` 曾得 6）
- `Number::sqrt` 对有理数 `p/q` 有完整化简：`sqrt(p/q) = sqrt(p·q)/q`，结果为精确根式
  （`sqr(1/2)` → MathIO `(1 / 2)*sqrt(2)`）。

### Expr 与 Evaluator（parser.rs）

AST：

```rust
pub enum Expr {
    Number(Number),
    Variable(String),          // 单小写字未知数 / ans / 全大写存储变量
    Binary(Box<Expr>, BinOp, Box<Expr>),
    Unary(UnaryOp, Box<Expr>),
    Pow(Box<Expr>, Box<Expr>),

`Evaluator` 持有运行态：`display_mode`、`angle_mode`、上一次结果 `ans`、以及 `/let` 存储的变量表 `vars: BTreeMap<String, Number>`。变量求值优先级：**显式替换（方程未知数）→ `ans` → 存储变量 → 未定义错误**。

### 解析器结构（递归下降）

入口链：`parse_system()`（逗号分隔方程组）→ `parse_equation()`（单个 `=`）→ 表达式。

```
parse_expression → parse_term → parse_unary → parse_power → parse_atom
      加减            乘除+隐式乘法      一元±         幂(右结合)    括号/绝对值/数/标识符
```

- **隐式乘法**：`parse_term` 中遇到数字、字母、`(`、`|` 自动按乘法解析，如 `3x`、`2(x+1)`；
- **绝对值 `| |`**：在 `parse_atom` 层解析（与括号同级），用 `abs_depth` 区分开/闭括号，避免闭合 `|` 被隐式乘法误吞；
- **后缀阶乘 `!`**：在 `parse_power` 中紧贴操作数处理，`2^3! = 2^(3!)`；生成内部函数名 `"fact"`（白名单不含 `fact`，用户无法直接输入 `fact(...)`）；
- **多参函数**：`(` 后支持逗号分隔参数列表，目前仅 `log(b, x)` 使用两参；
- **函数白名单**：`parser::FUNCTIONS` 是唯一来源（解析校验、多字母拆分判断、`main.rs` 高亮共用），
  新增函数只需改它与 `Evaluator::eval_function`；
- **标识符分类**：先查 `pi`/`e`/`ans`，再查单字母变量，再查全大写存储变量（`X`、`AB`、`PI_VAR`），
  其余按多字母变量序列拆分（`xy^2 = x*(y^2)`）；以 `e` 开头的变量串按"常数 e + 其余变量"处理
  （`2ex` → `2*e*x`、`ee` → `e^2`），多字母拆分只消费第一个字符并把位置回退给隐式乘法。

### 求值器中的参数校验（parser.rs::eval_function）

- `log(b, x)`：底数必须 > 0 且 **精确不为 1**（`base.as_rational().is_one()`，或与 1 的偏差 > 1e-40）。
  旧实现用 `base.rounded(0) == 1` 判断，会把 0.5/0.9/1.2 这类底数误判为 1；
- `exp`/`sinh`/`cosh`：`check_exp_range` 拦截 |x| > 10^6；
- `tanh`：|x| > 100 时直接返回 ±1——80 位精度下 `1 - tanh(x) = 2e^{-2x}/(1+e^{-2x}) < 1e-80` 已饱和，
  这与"避免 `exp(2x)` 参数失控"是同一件事（旧阈值 10^10 会先撞上 exp 的参数上限而误报错）；
- 三角 `sin/cos/tan/cot/sec/csc`：`check_trig_range` 拦截弧度参数 |x| ≥ 10^78
  （度模式先按 `×π/180` 折算出弧度量级）。

### 顶层入口 parse_and_eval

```rust
pub enum EvalResult {
    Value(Number),
    SdValue(Number),
    Factor(Expr),
    Equation(Expr, Expr),
    System(Vec<(Expr, Expr)>),
}
```

先尝试 `sd(...)`、`fac/factor(...)` 两层顶层函数，再解析方程组/等式，最后兜底为普通表达式求值（含恒等式检测与"两侧可化简为相等"判断）。

## 15. 各求解器逻辑

### trig.rs — 特殊角精确值

度模式下先将角度归一化到 `[0, 360)`，再映射到 `[0, 90]` 参考角查表（`15°` 步长的整分数、`pi` 的有理倍），用 `make_surd` / `make_double_surd` 构造 `(a + b√c)/d` 或双根式精确值；其余角度用 `BigFloat` 高精度三角函数，反三角对 `0, ±1/2, ±1, ±√3/2...` 等特殊值回填角度。

### solver_linear.rs — 线性方程组

`gaussian_elimination` 对增广矩阵选主元、消元、回代。返回唯一解 / 无解 / 无穷解三种信息（`LinearSolution`）。
`format_linear_solution(sol, mode)` 按 `DisplayMode` 输出，并给每项加 `=`/`≈`（与单方程输出一致）。

### solver_poly.rs — 多项式求根

- `extract_polynomial`（+ `collect_terms`）从 AST 提取升幂系数；`collect_terms` 支持把 `/let` 存储变量、`ans`、`(x+1)^n`（n≤64）展开为常数项或多项式；
- `solve_poly_full`：对分解后的因子**线性/二次精确**求解，`deg ≥ 3` 用 **Durand-Kerner**（Weierstrass）迭代求出**全部复数根**（自建 `Cx { re, im }` 复数算术，虚部接近 0 视为实根）。
  高次因子的求解做了四项针对性处理：
  - **初值**：n 个起点均匀撒在半径 `R = min(柯西界, max(|a₀/aₙ|^(1/n), 1))` 的圆上（角度错开半格）——柯西界对稀疏多项式过宽（`x^96+…+1` 的界为 2，而根全在单位圆上），几何估计更贴合真实根模；首次未收敛时退回柯西界半径重试一次；
  - **两阶段精度**：先用 40 位低精度粗收敛（每轮 O(n²) 复数运算，BigInt 位数减半、单轮开销约为全精度的 1/2~1/3），再用 80 位精化（牛顿型收敛，十余轮即达目标）；
  - **未收敛如实报错**：迭代跑满步数上限仍未收敛时返回错误提示，**不把中间值当根输出**（旧实现会把未收敛的迭代值直接输出，`x^100=1` 曾给出模约 1e21 的"根"）；
  - **Fast 次数护栏**：DK 每轮 O(n²)，实测 n≈200 约 25 秒、n≥300 超过 1 分钟，故 Fast 模式对 > 200 次的因子直接提示改用 `/mode deep`（Deep 不设限）；
- `newton_solve`：单根牛顿迭代，支持指定 `max_iter`；每步都做**发散保护**（`NEWTON_ABS_LIMIT = 10^6`，
  修正量或 |x| 越界即放弃该初值），退出时再校验残差消除假根；
- `format_solution(sol, mode)` 按 `DisplayMode` 输出根：MathIO 下精确根用符号（`1 / 2`、`sqrt(2)`），
  LineIO 下一律小数；`=`/`≈` 前缀由 `main.rs::solution_prefix` 按模式判定（LineIO 下 `sqrt(2)` 的小数展开标 `≈`）。

### solver_nonlinear.rs — 非线性方程组

两阶段牛顿：

1. **粗扫**：所有初值的网格笛卡尔积（含 0.5 步长细格），`max_iter=16`、容差 `1e-12`、雅可比**前向差分**，去重收集候选；
2. **精收敛**：对每个候选 `max_iter=80`、容差 `1e-45`、雅可比**中心差分**，去重后返回。

`same_solution` 用 `1e-12` 判定两个解是否重复。任一分量超过 `NEWTON_ABS_LIMIT` 即认为发散；
"步长极小"的提前返回也必须通过残差校验（`loose_tol = 1e-25`），避免返回平坦区假根。

### solver_factor.rs — 因式分解

内部以 `Poly`（单项式 `Mono`（变量指数向量）+ `BigRational` 系数，BTreeMap 合并）表示多项式：

1. `expr_to_poly` / `collect_expr_terms(expr, vars, evaluator, terms)` 把 AST 展开为有理系数多项式（支持 `^` 幂折叠，多项式底数 2..=64），其中 `ans` 与 `/let` 存储变量按数值代入常数项；
2. **单变量** `factor_univariate`：提取常数因子 → 取公因式 → **有理根定理**（`int_divisors` 枚举 ±p/q，用 u64 试除加速、规模上限 1e13）→ **综合除法**降幂 → 剩余二次因式用判别式拆根号（MathIO）或判不可约（LineIO）；
   走到二次残余说明有理根已枚举失败 ⇒ LineIO 下保留的二次因式在有理数域内**确定不可再分解**，附加"（有理数域内不可再分解）"提示；
   根式对（`SqrtPair`）的两个因式之间用 ` * ` 连接（`(x - sqrt(2)) * (x + sqrt(2))`）；
   根式前的分数系数加括号（`(1 / 2)*sqrt(2)`，整数系数不加，与 `display.rs` 的约定一致）；
3. **多元** `factor_multivariate`：沿坐标轴投影找线性因式（`find_linear_factor`）反复长除，`is_homogeneous` + `lift_univariate` 处理齐次多项式，指数向量相同因子合并（`push_factor_rep`）；
4. `factor_expr(evaluator, expr, mode)` 按当前显示模式决定分解域并输出乘积字符串；
5. **结果用 `FactorOutcome { factors, has_irreducible, truncated }` 区分两种"没算完"**：
   `has_irreducible`（该域内不可再分）→ "有理数域内不可再分解"；
   `truncated`（有理根候选或二次因子枚举超出预算）→ "候选枚举超出规模上限，结果可能不完整"。
   预算常量：`QUADRATIC_TRY_BUDGET = 5000` 次长除、`QUADRATIC_BMAX_LIMIT = 200000`。

### solver_fit.rs — 多项式函数拟合

输入若干 `(x, y)` 坐标（`P(x, y)` 额外表示顶点），求过这些点的多项式 / 由模板解出未知参数。
核心数据结构：

```rust
pub struct FitPoint  { pub is_vertex: bool, pub x: Expr, pub y: Expr }
pub struct FitTemplate { pub rhs: Expr, pub var: char }
pub struct FitInput  { pub points: Vec<FitPoint>, pub template: Option<FitTemplate> }
pub struct LinForm   { k: Number, terms: BTreeMap<String, Number> }  // k + Σ coeff·自由参数
pub struct FitSolution {
    pub params: Vec<(String, LinForm)>,  // 每个未知参数 = 自由参数的线性形式
    pub free: Vec<String>,               // 自由参数名
    pub coeffs: Vec<LinForm>,            // 化简后的升幂系数（一般式）
    pub var: char,
}
```

两条求解路径：

1. **无模板**（`solve_polynomial_fit` 的 `template == None` 分支）：普通坐标给出 1 个方程、顶点坐标
   额外补一条**解析导数行**（`[0, 1, 2a, 3a², …]` 在顶点横坐标处取值为 0，即 `f'(m)=0`），凑成范德蒙型
   线性方程组，交给 `solver_linear::gaussian_elimination`；`unique` 为真即得唯一多项式，否则提示约束不足/矛盾。
2. **有模板**：把每个未知参数视为未知量，构造基函数 `φ_j = extract_polynomial(模板第 j 项, var = 1) − g`
   （`g` 为模板中不含未知参数的常数项，**必须减去**，否则含常数偏移的模板会整体偏移），
   每个约束给出 `Σ φ_j(x_i)·p_j = y_i − g(x_i)` 的一行；自写 `rref()` 求行最简形，主元列参数写成
   `LinForm`，自由列参数作为自由参数 → 得到"参数关系式"。同时用 `check_param_linearity`（参数必须线性出现）
   与 `verify_solution`（回代残差 `10^(3·precision/4)` 容差）双重校验。

输出渲染：

- `format_fit_solution` **恒以 `y = …` 开头**（左值只是装饰，不采用 `f(x)`）；系数为分数或含空格/除号时加括号（`(1 / 2)*x^2`）；
- `format_vertex_form`：仅当"实际二次（首项非 0）且所有系数为常数"时追加顶点式 `y = a*(x - m)^2 + k`，
  其中 `m = -b/(2a)`、`k = c - b²/(4a)`；`m == 0` 或系数含自由参数时返回 `None`（不输出）；
- `format_fit_params`：依次输出 `参数 = 关系式` 与 `自由参数: …` 一行；
- 规模上限 `FIT_MAX_SIZE_FAST = 16`（约束/参数个数），超出提示 `/mode deep`，Deep 放开。

### solver_triangle.rs — 三角形求解

核心数据结构：

```rust
pub enum TriPart { Side(u8), Angle(u8), Height(u8) }   // 下标 0/1/2 → a-A / b-B / c-C
pub struct TriangleInput  { pub parts: Vec<(TriPart, Expr)> }   // 解析期不求值
pub struct TriangleSolution { /* 三边、三角（弧度）、三高、面积、周长、R、r */ }
```

`solve_triangle` 的四步：

1. **求值 + 规范化**：逐项 `evaluate_with_vars`；复数拒绝；边/高必须为正、角必须在 `(0, π)`
   （按 `Evaluator::angle_mode` 先把输入角度换算成**内部弧度**）；同名重复赋值只有值相同时才容忍。
2. **归约**（`complete_angles` + `reduce_heights`）：两角补齐第三角；高按
   `S = hA·a/2`、`hA = b·sinC = c·sinB`、`a·hA = b·hB = 2S` 转换成面积或边长。
   归约后若**一个长度都没有**，直接报"信息不足"（三个高或三个角只能定形状，
   三个高时还会补一行最简整数比 `a : b : c`）。
3. **解析优先、数值兜底**（`solve_analytic` → `solve_numeric`）：
   - SSS 用海伦公式求面积（`sqrt` 保精确）、**逐角各自用余弦定理**（不走 `π−A−B` 累减，
     才能保住 `90°`/`60°` 这类精确值）；SAS 用余弦定理求第三边；AAS/ASA 用正弦定理定比；
     SSA 按 `h = b·sinA` 与 `a` 的关系给 0/1/2 解；另有"两边+面积""一边+其对角+面积"两种归约情形。
   - 其余组合走 `(A, B, s=2R)` 参数化（`C = π−A−B`、`a = s·sinA`、`hA = s·sinB·sinC`）的
     多起点 Gauss-Newton（法方程 `JᵀJ Δ = −Jᵀ r`，角度种子取 `π/8` 的整数倍），解出后去重。
4. **校验 + 写回**：每个已知量都回代比对（超定矛盾在这里被拦住），通过后把已知量原样写回，
   再由 `R = abc/4S`、`r = S/(p/2)`、`hA = 2S/a` 派生其余量（全走 `Number` 精确运算）。

渲染 `format_triangle_solution` 固定 5 行（边 / 角 / 高 / 面积+周长 / 两半径），
每个值的 `=`/`≈` 由 `solve_aux::result_prefix` 决定；角度输出前用 `parser::radians_to_degrees`
把精确 `Pi(coeff)` 精确转成度数。多解时由 `handle_triangle` 加 `解 N:` 分段。

## 16. 方程处理主逻辑（main.rs）

`handle_input_result` 按 `EvalResult` 分派：

- `Value` / `SdValue` → `fmt_value` 按模式格式化并加 `=` / `≈` 前缀（`solve_aux::result_prefix`）。
  `SdValue` 的显示形式与显示模式**互换**（MathIO→小数、LineIO→符号），前缀也按互换后的模式判定
  （`sd(1/2)`：LineIO `= 1 / 2`、MathIO `= 0.5`）；
- `Factor` → 调 `solver_factor::factor_expr(&evaluator, expr, mode)`；
- `Equation` → `handle_equation`：收集变量并**过滤已存储大写变量** → 单变量走 `newton_with_guesses` / `solve_poly_full` 混合路径 → `solve_aux::collect_all_roots` 合并多解，再尝试 `format_periodic_roots` 识别**周期通式**；
- `System` → `handle_system`：先判全线性（走高斯消元），否则走多维牛顿；
- `Fit` → `handle_fit`：调 `solver_fit::solve_polynomial_fit` 解出参数/系数，输出 `y = …`（二次追加顶点式）。
  识别入口在 `parser::parse_and_eval`：`looks_like_polynomial_fit`（行首 `(` / `P(` / `p(` + 顶层逗号 + 尾字符白名单）
  通过后走 `Parser::parse_fit`，早于 `sd(…)` 判定，避免与函数调用冲突。
- `Triangle` → `handle_triangle`：调 `solver_triangle::solve_triangle`，输出 5 行（多解时以 `解 N:` 分段）。
  识别入口是 `parser::parse_triangle_call`，处理 `triangle(… )` 函数形式：括号内按**顶层逗号或空白**切分
  （`split_triangle_items` 深度感知，`log(2,8)` 里的逗号不会被切开），每项形如 `<记号>=<表达式>`。
  与 `sd`/`fac` 一致**只能是整个表达式的最外层函数**：`triangle` 出现在别处（`2*triangle(...)`）或
  `)` 之后还有内容，都直接报"必须是整个表达式的最外层函数"，**不回落**到常规文法（避免给出误导性提示）。
- `PrimeFac(n)` → `handle_primefac`：调 `primefac::format_prime_factorization` 输出 `12 = 2^2 * 3`。
  识别入口是 `parser::parse_primefac`，同样是**最外层限定**，且**在解析期就把括号内表达式求值并校验**成非零整数
  （小数/0 报错，含自由变量则由求值错误报出）；因此 `EvalResult::PrimeFac` 直接携带 `Number`，不需要新的 `Expr` 变体。
  另外 `fac`/`factor` 的 `Factor` 分支会先试 `eval_nonzero_integer`，**非零整数则走同一条素因数分解**，
  其余情况才回到多项式分解——所以 `fac(12)` 与 `primefac(12)` 等价，而 `fac(x^2-4)`、`fac(0)`、`fac(2.5)` 行为不变。

### 会话状态持久化（state.rs）

`~/.hipercalc_state`（与 `.hipercalc_history` 同目录）保存显示/角度/计算模式、全部 `/let` 变量与 `/set` 颜色：

| 行格式 | 含义 |
|---|---|
| `display=mathio\|lineio`、`angle=deg\|rad`、`calc=fast\|deep` | 三个模式 |
| `var:NAME=E:<MathIO 表达式>` | 精确值：存符号形式（`1 / 3`、`(1 / 2)*sqrt(2)`、`pi`），加载时重新解析还原，**无损** |
| `var:NAME=A:<value>:<precision>` | 近似值：BigFloat 的内部十进制表示（尾数 + 小数位数），直接还原，**无损** |
| `color:<类别>=<颜色名>` | `/set` 设置的高亮颜色（如 `color:functions=red`），加载时校验类别与颜色名，非法项跳过 |

- 精确值之所以不直接序列化内部结构：`ExactExpr` 是"多项 + 分母"的复合结构，序列化复杂且易随实现变动，
  而 MathIO 的符号输出本就是可解析表达式，重新解析即可精确还原（用临时 `Evaluator`，不污染会话的 `ans`/`vars`）；
- 每次变更（`/let`、`/del`、`/mode`、`/set`）后立即调用 `persist_state()` 落盘，退出时再存一次；
- 加载时对变量名与值都做校验，非法行跳过而不报错；文件缺失即用默认设置。

### 颜色高亮（main.rs）

- `ColorConfig` 持有 9 个类别（functions/operators/commands/brackets/constants/numbers/prompt/result/error）的颜色，
  `set_category`/`get_category`/`to_pairs` 供 `/set` 与状态文件读写共用；类别与颜色名集中在
  `COLOR_CATEGORIES` / `COLOR_OPTIONS` 两张常量表（英文名 + 中文标注 + 颜色值），解析与反查都走它们；
- `colorize_text(line, colors, command_anywhere)` 与 `colorize_result(line, colors)` 是仅有的两个着色入口，
  二者共用底层 `colorize_impl(line, colors, command_anywhere, base)`：REPL 输入行（`command_anywhere=false`，
  只有行首 `/xxx` 算指令）与 `/help` 正文、各用法提示（`true`）走 `base=None`（未识别文本原样输出）；
  **结果行**走 `colorize_result`（`base=Some(colors.result)`，未识别文本用 result 色打底）。
  这样同一关键词在输入行与结果行颜色一致；
- 结果行**整行只用单一 result 色**是旧行为，看起来和没高亮一样，已废弃；
- `OPS` 里除 `+ - * / ^ ! =` 还有 `≈ × ·`——后三个只出现在**结果**串里（`≈` 前缀、科学计数法的 `×`、通式的 `k·π`）；
- `/help` 为无边框简版（`HELP_TEXT` 常量）：`【…】` 小节标题用 result 颜色加粗，正文交给 `colorize_text`；
- 仅输入 `/set` 时先打印用法（类别、颜色都带中文标注）再列出当前颜色（颜色名用各自的颜色显示）。

### 界面语言实现（i18n.rs）

- 词条表以**简体中文原文为键**：`(简体, 繁體, English)`，运行时对**整行输出**做模式匹配翻译
  （`{0}`/`{1}` 标注插值位置，先把插值抓出来再填进目标语言模板，因此词序可按语言调整）；
- 行内可能含 ANSI 颜色码：翻译前先按转义序列切段，只翻译纯文本段再拼回，
  所以 `"错误".red() + ": " + 消息` 这种拼接串也能正确翻译；一段里有多处可翻译片段时循环替换（上限 8 轮）；
- 单字词条（颜色名）只允许整段精确匹配，避免到处误替换；简体中文为默认，直接原样返回（零开销）；
- 未命中的字符串原样保留，**不会报错**——新增文案时把简体原文加进 `TABLE` 即可；
- `main.rs` 的所有控制台输出统一走 `lprint!` / `leprint!` / `lprint_inline!` 宏（内部调用 `i18n::t`），
  `/help` 的正文则按语言整份切换（`help_text()`）。

### 运算计时（main.rs）

`handle_input_result` 里用 `Timing` 包住**"解析 + 结果生成"整段**（结果格式化阶段——
方程通式识别、根收集、因式分解等常常比 `parse_and_eval` 本身更耗时）：

- `Timing::begin()`：stdout 是终端时起一个刷新线程（`mpsc::channel` + `recv_timeout(100ms)`，
  关闭通道即可让线程立即退出，无需等待），用 `\r用时：N秒` 动态刷新整秒；
- 各 handler（`handle_equation`/`handle_system`/`handle_factor`）只负责**生成结果字符串**，
  全部计算完成后统一调用 `Timing::stop_dynamic()`：停线程并打印 `\r` + 24 空格 + `\r` 清行，
  随后单次 `println!` 打印的结果正好**覆盖**这一行；
- 最后用 `timing.elapsed_text()` 在结果下一行输出 `用时：N秒`（不足 1 秒 → `用时：<1秒`），
  该行同样走 `lprint!`——写成 `println!` 会绕过 i18n，英/繁模式下会留在中文。

管道/重定向时 stdout 不是终端（`std::io::IsTerminal`），跳过动态刷新，避免把 `\r` 写进输出。

### solve_aux.rs — 辅助工具

- `result_prefix`：按显示模式与精确性返回 `"="` / `"≈"`
  （LineIO 下要求有理数**能完整写出**：整数，或十进制有效数字 ≤ 20 位的有限小数，见 `finite_decimal_fits`）；
- `float_to_exact_rational`：近似值与简单分数足够接近时回填精确有理数 `(p, q)`（返回分子分母，
  由调用方按显示模式输出 `1 / 2` 或 `0.5`），容差随量级缩放（`tol = 1e-12·min(|x|,1)`），
  极小根不会被回填成 `0`；
- `format_periodic_roots(roots, var, angle_mode)`：检测单周期等差数列或交替两族间距，定出公共周期 `d`，
  把 `d` 与各残基用**分母 ≤ 12 的有理逼近**表示成 `(p/q)·π`，再按 `angle_mode` 渲染成
  `x = π/6 + k·2π  或  5π/6 + k·2π，k 为整数` 或 `x = 30 + k·360  或  150 + k·360，k 为整数`。
  入参若为度值会先 `×π/180` 折算成弧度，因此**两种模式的判定完全同构**（`pi_frac_str` / `deg_str` 只管标签）。
  判定前只保留 `±3π` 窗口内的根（去掉远端污染），残基去重用**相对 + 绝对**容差（`tol·max(|a|,|b|) + 1e-40`），
  并按**识别标签**（π 的有理倍）再次去重，避免同一族重复输出；
- `best_rational` / `pi_ratio`：在分母 ≤ 12 的分数里取最接近者（取代原先的固定候选表，
  才能覆盖 `5π/3` 这类表外的角）；`deg_str` 把 `(p,q)` 渲染成精确的度数（`(1,6)→30`、`(1,8)→22.5`）；
- `collect_all_roots`：多组初值 + 两阶段牛顿（粗扫 1e-8 → 精收敛 1e-12）收集并去重；
  方程含"以未知量为角度的三角函数"且当前是角度模式时，初值整体 `×180/π`（见 `equation::has_trig_of_var`）。

```
用户输入
  │
  ▼
main.rs：Timing::begin()（终端里启动 \r 动态计时线程）
  │
  ▼
parse_and_eval（parser.rs）
  ├── looks_like_polynomial_fit → parse_fit（坐标 + 可选解析式）
  ├── triangle(...) → parse_triangle_call（最外层函数；括号内空白/逗号分隔的赋值）
  ├── sd(...) / fac(...) 顶层识别
  ├── parse_system→parse_equation→表达式解析
  │      └── 数值护栏查询 calc_mode::is_deep()：Fast 超限报错 / Deep 放行
  │
  ▼
EvalResult 分派（main.rs）
  ├── Value ──► 求值（Evaluator 精确优先）────► display + 前缀 输出
  ├── Factor ─► solver_factor::factor_expr
  ├── Equation ─► 过滤存储变量 → 多项式/牛顿求根 → 通式识别 → 输出
  ├── Fit ────► solver_fit::solve_polynomial_fit（一般式 + 顶点式）
  ├── Triangle ► solver_triangle::solve_triangle（解析解 / 数值兜底）
  └── System ──► 线性 ? solver_linear（高斯消元）
                    : solver_nonlinear（多维牛顿）
  │
  ▼
Timing::stop_dynamic()（清行动态计时）→ 结果覆盖该行 → 下一行输出 用时：N秒
